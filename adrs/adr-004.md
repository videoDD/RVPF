## 1. Context
Virtual Production workflows struggle with discrepancies between live performance execution and recorded playback. When live sensor inputs (e.g., DMX triggers, MIDI actions) use different processing paths than recorded animation or timeline tracks, logic must be duplicated, introducing timing drift and runtime errors.

---

## 2. Decision
The RVPF execution model anchors to a **Master Timeline Authority** (realized in the Unreal Engine reference implementation via the **Sequencer** and **Take Recorder**). 

All external and synthetic signals are converted into the normalized `FStudioImpulse` model and synchronized with the master timeline. Downstream `StudioObjects` and Context Resolvers process impulses agnostically, irrespective of whether the source is a live hardware transport or a recorded Sequencer playback track.

---

## 3. Consequences
* **Positive:** Unified execution path: Live control, recording, playback, and automated simulation share identical logic.
* **Positive:** Native synchronization with cinematic pipelines, frame rates, and timecode standards.
* **Positive:** Fully deterministic take reproducibility for post-production and digital twin audits.
* **Negative:** Demands strict clock synchronization (PTP, Genlock, LTC) between external input sources and the real-time engine's master clock.
