## 1. Context
If a system dispatches business events for every incoming data packet (such as a 60 Hz or 120 Hz continuous tracking stream), the framework suffers from event flooding, non-deterministic race conditions, and performance degradation. The framework requires a deterministic gating mechanism that triggers operations only when meaningful state changes occur.

---

## 2. Decision
Semantic **Events** arise exclusively from a verified transition within an evaluated Context or State Machine (**State Transition**). Impulses alone do not generate events. Continuous incoming telemetry updates internal state metrics, but an event (e.g., `ActorEnteredStage`) is dispatched only when a contextual boundary is crossed (e.g., transitioning from `ActorOutsideStage` to `ActorInsideStage`).

---

## 3. Consequences
* **Positive:** Completely prevents event flooding during continuous high-frequency sensor streaming.
* **Positive:** Guarantees deterministic, traceable rule evaluation.
* **Positive:** Enforces clean separation between continuous telemetry (Impulses) and discrete business occurrences (Events).
* **Negative:** Context evaluation must maintain state history to compute state differences (`PreviousState` vs. `CurrentState`).
