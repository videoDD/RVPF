# ADR-003: Event Generation via Context Transitions

## Status
Accepted

## Context
If the system generates a business event for every incoming impulse (e.g., every frame a tracker sends a new coordinate), the framework will be flooded with redundant events, causing performance bottlenecks and non-deterministic behavior. We need a deterministic mechanism to trigger actions only when something semantically relevant happens.

## Decision
Semantic **Events** arise *exclusively* from a change in an existing context (a State Transition). Impulses alone do not generate events. For example, continuous tracking impulses update the state, but they only generate an event (e.g., `ActorEnteredStage`) when the contextual interpretation changes from `ActorOutsideStage` to `ActorInsideStage`.

## Consequences
* **Positive:** Prevents event flooding and performance degradation when states remain unchanged.
* **Positive:** Enforces a clear semantic description of system behavior.
* **Positive:** Creates a robust, highly optimized foundation for deterministic rule processing.
